# Exercise 4 – Decision-Making Scenario

## 1. Situation
GitHub Copilot suggests using code from an unknown open-source repository.

## 2. Should We Include the Code Directly?

No. We should not directly include code from an unknown repository without reviewing and verifying it. It may contain security vulnerabilities, malicious code, licensing restrictions, or incorrect functionality.

## 3. Checks That Must Be Performed First

Before using the suggested code, perform the following checks:

1. **Source Verification:** Check the repository owner, source URL, contributors, and project credibility.
2. **Code Quality:** Review the code for errors, unnecessary operations, and maintainability.
3. **Security Audit:** Check for malware, malicious scripts, vulnerabilities, and exposed credentials.
4. **License Verification:** Identify the open-source license and ensure it permits the intended use.
5. **Dependency Check:** Verify that external libraries and dependencies are safe and trustworthy.
6. **Testing:** Run the code in a controlled environment and perform appropriate test cases.

## 4. How to Document AI Contribution Ethically

- Mention that GitHub Copilot or another AI tool assisted in generating the code.
- Identify the original source repository when applicable.
- Follow the repository's license and attribution requirements.
- Review, test, and modify AI-generated code before using it.
- Clearly distinguish original contributions from third-party code.

## 5. Final Decision

The suggested code should not be included directly. It should first undergo source verification, security checks, license verification, and testing.

Only after all checks are satisfactory should the code be considered for integration into the project.

## 6. Conclusion

AI-generated code can improve development speed, but developers remain responsible for ensuring that the code is secure, legal, reliable, and ethically used. Human review and proper documentation are essential before accepting AI-generated suggestions.
